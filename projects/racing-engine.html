Custom Python Engine — Racing Game

Year 2024
Category Software Engineering
Duration 2 Months
Language Pure Python + Pygame

Project Overview

A real-time racing game engine built entirely from scratch in Python, with zero external game frameworks. The project validates core software engineering fundamentals — event-driven architecture, state management, rendering pipelines, and performance optimization — all in a visually engaging, playable format.

Technical Details

  • Custom event handling system with subscriber/publisher pattern for decoupled input processing
  • Frame-rate-independent state management using delta-time accumulation for consistent physics regardless of hardware
  • Sprite-level collision detection using axis-aligned bounding box (AABB) intersection with pixel-perfect refinement
  • Dynamic difficulty scaling based on player score — obstacle spawn rate, speed, and pattern complexity increase progressively
  • Modular rendering pipeline with layered draw-order management (background → track → obstacles → player → HUD)
  • Object-oriented architecture with clean separation of concerns: GameEngine, InputManager, Renderer, PhysicsWorld, and UIOverlay

Challenges & Solutions

The main performance challenge was Python's inherent speed limitations for real-time rendering. Profiling revealed that the collision detection loop was the bottleneck. Implementing spatial partitioning (grid-based bucketing) reduced collision checks from O(n²) to O(n), maintaining a steady 60 FPS with up to 50 simultaneous on-screen sprites.

Ensuring frame-rate-independent physics was tricky — naive implementations caused the game to run at different speeds on different machines. A fixed-timestep accumulator loop with interpolated rendering solved this, providing consistent game speed across hardware.
